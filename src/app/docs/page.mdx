# How Tickets works

Create an event, map its entrances, print tickets and check guests in at the door, even when the signal drops.

<Clip name="overview-tour" alt="A quick tour: creating an event, generating tickets and scanning one in" />

## The short version

1. **An organizer creates an event** with a venue, date and time.
2. **They add entrances** if guests use different doors, such as a North Gate and a VIP entrance.
3. **They generate tickets in batches** and print them as A4 sheets, ten tickets to a page. Each ticket has a six-character code.
4. **They add ticket scanners**, the people who check guests in at the door, and assign each one to an entrance.
5. **On the night, scanners type each guest's code** into the scanning page. The result appears instantly: admitted, already used, wrong entrance, and so on.
6. **Organizers watch arrivals live** on the event's overview and activity tabs.

## Who does what

| Role | What they see |
|---|---|
| **Admin** | Everything: every event, the People & roles screen, and scanning anywhere. |
| **Event organizer** | Can create events and manage any event they created or were invited to. |
| **Ticket scanner** | Only the scanning page, and only for the events they're assigned to. |
| **User** | A new account with no access yet. They see a page asking them to contact an admin or organizer. |

Read more in [Signing in & roles](/docs/getting-started).

## Built for the door

- **Works offline.** Every scanner's device keeps a copy of the tickets for their events, so codes are checked on the device itself. Scans upload automatically when the connection comes back. See [Offline & sync](/docs/offline-and-sync).
- **One ticket, one entry.** A code that's already been used shows when and where it was first admitted.
- **Right door, every time.** A guest at the wrong entrance is redirected by name, with your directions.
- **Everything updates live.** Ticket counts, arrivals and scanner changes appear on every device within about a second.
